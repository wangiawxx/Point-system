# 多门店升级预留说明

当前是单门店模式：一套 NestJS 后端和一个 SQLite 数据库文件。积分、PK、排行榜和登录业务都通过 Prisma 访问数据，后续升级数据库不需要重写这些接口。

## 何时需要升级

出现以下情况时，建议切换 PostgreSQL：

- 新增多个门店并需要数据隔离。
- 多人频繁同时录入积分或结算 PK。
- 需要部署多个后端实例提升并发能力。

## 后续升级步骤

1. 准备 PostgreSQL 数据库。
2. 将 Prisma 数据源从 `sqlite` 改为 `postgresql`，先在测试环境迁移。
3. 现有核心表已经预留 `storeId`，增加门店时按门店隔离用户、积分流水、PK 和管理员数据。
4. 登录 JWT 增加 `storeId`，所有查询自动附加门店条件。
5. 将手机号、管理员账号、PK 预约唯一性改为“门店范围内唯一”。
6. 备份 SQLite 数据，导入为第一个门店；核对用户积分与积分流水后再切换生产流量。

## 当前已保留的安全规则

- 积分操作编号可防止重复入账。
- 同一双方、同一时间的 PK 在数据库层面唯一。
- 积分流水和积分余额在同一事务中写入。
- 排行和趋势都由已保存的积分流水计算。
